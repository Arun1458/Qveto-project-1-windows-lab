# Week 1 — Network Validation Report

Project: Windows Exploitation & Privilege Escalation Lab
Date: 18-10-2026
Prepared by: dhruv-sain-hub

## 1. Objective

Verify IPv4 connectivity between the Windows 11 and Kali Linux VMs over the Internal Network LabNet.

## 2. Expected Configuration

- Network: LabNet
- Subnet: 10.10.10.0/24
- Windows: 10.10.10.20/24
- Kali: 10.10.10.10/24

## 3. Initial Troubleshooting

The initial ping from Kali to Windows failed. During troubleshooting, the relevant Windows inbound ICMPv4 Echo Request rule was found to be disabled.

The rule was enabled for the lab ping test. Windows Firewall was not intentionally disabled.

## 4. Test Results

### Test A — Windows to Kali

- Source: 10.10.10.20
- Destination: 10.10.10.10
- Command: `ping 10.10.10.10`
- Result: Successful
- Packet loss: 0%

### Test B — Kali to Windows

- Source: 10.10.10.10
- Destination: 10.10.10.20
- Command: `ping -c 4 10.10.10.20`
- Result after rule change: Successful
- Packet loss: 0%

## 5. Conclusion

Bidirectional ICMP connectivity was verified between the two VMs.

This confirms that ICMP echo traffic can pass in both directions. It does not independently confirm that every network service is reachable or that the environment has complete isolation.

## 7. Evidence Checklist

- [x] Windows `ipconfig /all` and `route print -4` output (E11)
- [x] Kali `ip -4 addr show dev eth0` after restart (E12, E16)
- [x] Successful Windows-to-Kali ping
- [x] Successful Kali-to-Windows ping

Windows and Kali route outputs show no default route, but the Windows interface lists three IPv6 DNS server entries, and Kali resolver output is not present. The Kali snapshot details also display NAT, which differs from the current LabNet setting and must be reconciled before relying on that snapshot for recovery.
